# gpui-table-mcp Architecture

`gpui-table-mcp` is the experimental public integration crate for exposing
generated table filter state as MCP query tools.

## Boundary

The crate does not instantiate GPUI windows, table delegates, or filter
widgets. It owns:

1. MCP-facing table and filter descriptors.
1. JSON argument decoding into generated `XxxFilterValues`.
1. Table-specific query registry wrappers.
1. In-memory query execution for examples and tests.

Shared tool result, tool server, `rmcp` stdio serving, and schema helper
mechanics come from `component-shape-mcp`.

Applications own the query handler. They usually register handlers with
`#[gpui_table::mcp_query]`, which infers a row type from a `TableQuery<Row>`
first parameter for custom backends or a zero-argument
`Result<Vec<Row>, E>` return type for local row sources. Local row sources are
called for each MCP query. The inferred row type must implement `McpTable`,
which is generated by opting the row into `#[gpui_table(mcp)]`. The attribute
emits `McpQueryHandlerRegistration` inventory items.
`server()` returns a built shared `component-shape-mcp` server with those
handler registrations already applied. `server_named(name, version)` uses
application-owned server metadata. `builder()` and `builder_named(name,
version)` expose the deferred builder path for callers that want setup errors
reported from `.build()?`, `.serve_stdio().await`, or
`.serve_stdio_blocking()`.
`serve_stdio()` and `serve_stdio_blocking()` are convenience entry points for
serving the default generated registry directly.
`register(&mut server)` returns the same setup errors while adding discovered
table handlers into an application-owned shared server
so tables can be served beside form submit tools or other component-shape MCP
integrations. Custom query handlers can be synchronous or async and return
`Result<TableQueryResult<Row>, E>`. The lower-level `table::<Row>(&mut server)`
API remains available for custom server composition; `query` registers handlers
with the same exact row-result contract.
`rows` registers fixed local rows, while `row_source` and `row_source_async`
call local row sources for each MCP query.
Manual tool registration returns `Result<(), McpToolError>`.

## Generated Input

`gpui-table-derive` emits `McpTable` only when the `mcp` feature is enabled and
the table opts in with `#[gpui_table(mcp)]`. The generated implementation:

1. Builds `McpTableFilter` metadata from the same filter field plans used for
   `XxxFilterEntities`, `XxxFilterValues`, and `Matchable`.
   Bare `#[gpui_table(filter)]` fields have already been resolved to inferred
   built-in shapes by `gpui-table-derive`; explicit `filter(...)` paths use the
   selected shape directly.
   Tables without filter fields emit an empty `XxxFilterValues` type and accept
   only reserved pagination arguments.
1. Builds each filter descriptor with `McpTableFilter::for_shape::<Shape>` so
   the filter type and schema hook are selected through the same
   `McpFilterShape` implementation.
1. Carries shared `McpToolMetadata` so
   `#[gpui_table(mcp(name = ..., title = ..., description = ...))]` can
   override generated tool metadata without changing filter decoding.
1. Decodes top-level filter field arguments plus reserved `limit` and `offset`
   pagination arguments through `McpArguments`.
1. Calls `<Shape as McpFilterShape>::decode_filter(...)` for each present
   filter argument.
1. Calls `McpArguments::finish` so unknown arguments become tool execution
   errors.
1. Submits an `McpTableRegistration` inventory item.

## Filter Decoding

Built-in filter shapes decode as follows:

- `TextFilter`: JSON string to `TextValue`.
- `FacetedFilter<T>`: JSON string array to `HashSet<T>` using
  `FilterValue::from_filter_string`.
- `NumberRangeFilter`: `{ "min": number|string|null, "max": ... }` to
  `RangeValue<rust_decimal::Decimal>`.
- `DateRangeFilter`: `{ "min": "YYYY-MM-DD", "max": "YYYY-MM-DD" }` to
  `RangeValue<chrono::NaiveDate>`.

Custom shapes must implement `McpFilterShape`. Common raw-value filters can
derive that impl through `gpui_table::McpFilterShape`, which decodes
`Shape::RawValue` with serde and uses `McpJsonSchema` for the fallback schema.
`McpJsonSchema` supports named structs, tuple or named transparent newtypes,
fieldless enums, and common containers; it follows serde deserialize names, enum aliases,
skip/default metadata, and rejects flattened fields that require a manual
schema.
That keeps non-GPUI decoding explicit and avoids assuming every filter widget
has an MCP-safe JSON shape. `McpRange<T>` gives custom range filters an object
raw value that decodes from `{ "min": ..., "max": ... }` and publishes typed
schema metadata. Derived `McpFilterShape` impls publish the raw value schema,
so default schema and default decoding stay coupled. Implement
`McpFilterShape` manually when the shape needs richer schema metadata, such as
enumerated facet values, or custom decoding.

## MCP Runtime

The stdio server is delegated to `component-shape-mcp`, which implements
`rmcp::ServerHandler` for the generic server and serves it over
`rmcp::transport::stdio`. The narrow proof-of-concept surface remains:

- `initialize`
- `tools/list`
- `tools/call`
- `shutdown`

Tool results return `structuredContent` and text content. Filter validation
failures are returned as tool execution errors with `isError: true`; malformed
protocol requests remain `rmcp` protocol errors.
